# TowerFlow — Smart Building Management (frontend prototype)

React + Vite + TypeScript + Tailwind + React Router + Zustand + Recharts + Framer Motion + React Hook Form + Zod.
Frontend-only: JSON seed data, persisted to `localStorage` (keys prefixed `tower_`).

## Setup
```bash
npm install
npm run dev        # http://localhost:5173
npm run typecheck  # tsc --noEmit
npm run build
npm run seed       # regenerate src/data/*.json (deterministic)
```
Reset demo data any time: Settings → Reset demo data, or the purple flask button (bottom-left) → Reset all data.

## Workflows (all wired through shared state)
1. **Visitor** — Guard registers (photo → details → confirm) → host notified (in-app + WhatsApp + email logs) → host Approve / Reject / Request info → guard "Allow Entry" → live timer → "Mark Exit" → dashboards, live page, analytics update.
2. **Ticket** — Office raises ticket → admin sees recommended staff (availability → location → workload → skill → rating) → Assign (creates linked task + WhatsApp) → staff Accept → Start → Complete → ticket RESOLVED → office confirms + rates → CLOSED.
3. **Task** — Admin/Supervisor assigns → staff accepts/starts/updates progress/completes → supervisor verifies & rates (quality, speed, professionalism, cleanliness) → staff rating & performance charts update.
In demo mode (default) admins can also click the staff buttons; or use the demo panel (flask button).

## Architecture
```
src/
  app/            App, routes (role guards), providers
  components/ui/  Button, Badge, Modal, Drawer, DataTable, Form, StatCard, Timeline, Toast …
  components/business/  CrudPage + CrudForm (RHF+Zod), VisitorCard/Actions, TaskForm, TicketForm, FloorMap, BuildingViz …
  components/layout/    Sidebar, Topbar, CommandPalette, DemoPanel
  components/charts/    Recharts wrappers
  data/           JSON seed (generated by scripts/generateSeed.mjs)
  hooks/          useVisitors, useTickets, useTasks, useEmployees, useOffices, useLookups, useMe
  layouts/        AppLayout (admin/supervisor/office/staff), GuardLayout
  pages/          one folder per module
  services/       core (audit/notify/messages), visitor/ticket/task/employee/office/notification/demo services, storageService
  store/db.ts     single Zustand store: all collections + auth/theme/toasts, persisted per collection
  utils/          constants, permissions (RBAC matrix), helpers, dateUtils
```
**Data model** — normalised by ID: `office.floorId/towerId/tenantId`, `visitor.officeId/hostId/guardId`, `ticket.officeId/reporterId/assignedEmployeeId/taskId`, `task.assignedEmployeeId/supervisorId/ticketId`, `employee.supervisorId`. Names are resolved at render time via `useLookups()`, so renaming an office/tenant updates every screen.

## Replacing JSON/localStorage with a REST API
- Business rules live in `src/services/*Service.ts`; they call `db().add/patch/remove`. Replace those calls with `await api.post/patch/delete(...)` and refetch (or use React Query).
- `src/store/db.ts` `loadDb()` is the only place that reads seed/localStorage; swap it for initial fetches per collection.
- `storageService.ts` mirrors a repository interface (get/set/update/delete/clear).
- `utils/permissions.ts` becomes server-issued claims; `login()` becomes `POST /auth/login` returning a JWT.
- Simulated WhatsApp/email (`services/core.ts → sendMessage`) becomes a backend job; keep the log table as the read model.

## Known prototype limits
- Notification delivery, WhatsApp and email are simulated (no network calls). Photos/attachments are stored as base64/file names in localStorage (~5 MB browser limit).
- Auto-reject timeout setting is stored but not enforced.
